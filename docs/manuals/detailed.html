1. 시스템 개요 및 구성

1.1 제품 개요

Smart Signage는 Electron + Next.js 기반의 윈도우 데스크톱 디지털 사이니지 솔루션입니다. 단일 호스트 PC에서 편집기와 사이니지 출력을 동시에 운영하며, 옵션으로 PN-8080 HDMI 매트릭스를 직접 제어합니다.

2. 설치 및 첫 실행

2.1 설치

  1. 배포 받은 NSIS 인스톨러 (Smart Signage-1.6.0-x64.exe) 실행.
  2. 설치 경로 선택 (기본 C:\Program Files\Smart Signage).
  3. 설치 완료 후 바탕화면 / 시작 메뉴에 Smart Signage 바로가기 생성.

2.2 첫 실행

  1. 바로가기 실행 → Electron 메인 프로세스 부팅 (1~3초).
  2. 1번 모니터에 편집기 BrowserWindow 표시.
  3. 2+3+4번 모니터(Surround 디스플레이)에 사이니지 BrowserWindow가 hidden 상태로 대기.
  4. SQLite DB가 자동 생성됨: %APPDATA%\signage-app\signage.db

2.3 NVIDIA Surround 사전 설정

3개 모니터를 하나의 큰 디스플레이로 묶기 위해 NVIDIA Control Panel에서 Surround를 미리 활성화해야 합니다.

  1. NVIDIA Control Panel → 3D Settings → Configure Surround, PhysX
  2. "Span displays with Surround" 체크 → 3개 모니터 선택 → Apply.
  3. Windows 디스플레이 설정에서 2번째 디스플레이가 5760×1080 또는 5760×1200으로 인식되는지 확인.
세로 해상도는 모니터 베젤 보정 여부에 따라 1080 또는 1200으로 잡힙니다. 앱의 signage.resolution 옵션에서 두 해상도를 토글할 수 있습니다 (§5.1).

4. 슬라이드 관리

4.1 슬라이드 생성

  • SlideList 하단 + 슬라이드 추가 클릭.
  • 또는 Toolbar의 템플릿 메뉴에서 기존 템플릿 적용.

4.2 편집

  • SlideEditor 영역에서 TipTap 기반으로 텍스트 입력.
  • 지원: 폰트 패밀리 · 색상 · 굵게/기울임/밑줄 · 좌/중/우 정렬 · 배경 색상.
  • 이미지 가져오기 → Toolbar 가져오기 → 이미지.
  • HWPX(한글) 가져오기 → Toolbar 가져오기 → HWPX.

4.3 정렬 및 삭제

  • SlideList에서 드래그하여 순서 변경.
  • 슬라이드 우클릭 → 삭제.

4.4 사이니지 모드 (v1.4.0+)

각 슬라이드는 Surround 또는 Individual 모드 중 하나로 작성됩니다.

모드설명
Surround5760×1080(/1200) 단일 캔버스로 작성. 모든 모니터에 가로로 연결된 한 화면.
Individual1920×h로 작성된 슬라이드가 3개 모니터에 각각 동일하게 타일링되어 표시.

현재 운영 옵션의 signage.mode 값에 따라 SlideList가 자동 필터링됩니다.

5. 사이니지 출력

5.1 해상도 (signage.resolution)

Preview 영역 상단 콤보박스에서 5760×1080 또는 5760×1200을 선택합니다. 변경 시 편집기/프리뷰/실제 사이니지 출력 모두 자동으로 스케일이 조정됩니다.

Surround 출력 시 베젤 보정 옵션 여부에 따라 세로 해상도가 달라질 수 있습니다. 실제 모니터가 1200으로 인식되면 1200을 선택해야 검은 띠가 생기지 않습니다.

5.2 모드 (signage.mode)

운영 옵션 패널에서 Surround / Individual 토글. 슬라이드 자동 필터링 (§4.4 참고).

5.2.1 출력 모니터 지정 v1.7.0

NVIDIA Surround가 운영 중 OS/드라이버 사유로 해제되면 3개 모니터가 따로 인식되며, 이전(≤v1.6) 자동 선택은 그중 한 장에 3타일을 압축 표시해 사용 불능 상태가 됐다. v1.7부터 Individual 모드에서 출력할 모니터를 운영자가 직접 지정할 수 있다.

  • 운영 옵션 → 출력 모니터 콤보 (개별모드에서만 표시).
  • "자동 — 첫 확장 모니터" 또는 감지된 확장 모니터 중 선택.
  • 지정한 모니터에 1슬라이드가 native 1920×1080으로 단독 표시 (타일링 OFF).
  • 저장된 모니터가 다음 부팅에 없어지면 첫 확장 모니터로 자동 폴백 + main.log 경고.
  • 디스플레이 연결/해제 시 콤보 목록이 자동 갱신되며 placement도 즉시 재적용.
상황v1.7 동작
Surround 활성, 개별모드5760×1080 가상 모니터에 ×3 타일 (v1.6과 동일)
Surround 해제, 개별 + 모니터 지정지정한 1920×1080 모니터에 1슬라이드 단독 표시

서라운드 모드출력 모니터 콤보 비표시 — 기존 자동 선택 유지
v1.7 Preview 변경: Individual 모드에서 우측 패널 Preview가 항상 1920×1080 비율로 표시됩니다 (이전엔 5760+3분할선이 Surround와 동일하게 보여 혼동 유발). PlaybackControls의 1/N 카운터도 현재 모드의 슬라이드 수만 집계합니다.

5.3 페이지 전환 fade (slide.transitionSec)

슬라이드 간 페이드 시간을 초 단위로 지정합니다 (0~5초, 0.1초 단위). v1.3.0에서 true crossfade 가 적용되어 페이드 중 검은 화면이 보이지 않습니다.

5.4 슬라이드 여백 (slide.padding)

슬라이드 콘텐츠 사방 여백을 픽셀 단위로 지정합니다.

5.5 사이니지 표시 / 숨김

  • PlaybackControls 영역의 사이니지에 표시 버튼 클릭 → Surround 모니터에 BrowserWindow가 풀스크린으로 표시됩니다.
  • 표시 중에는 같은 버튼이 사이니지 숨김 으로 바뀝니다.

7. 매트릭스 제어 (PN-8080)

7.1 개요

PN-8080은 8입력 × 8출력 HDMI 매트릭스로, 이더넷 TCP/8000 포트의 ASCII 프로토콜로 제어됩니다. Smart Signage는 이를 직접 제어하여 외부 영상 라우팅을 운영자 한 화면에서 처리합니다.

7.2 연결

  1. 우측 매트릭스 제어 헤더 ▶ 클릭 → 펼치기.
  2. IP: PN-8080의 IP 주소 (기본 192.168.10.199).
  3. 포트: 8000 (변경 불필요).
  4. 연결 클릭 → 연결 시도. 상태 표시기:
    • 🟢 연결됨
    • 🟡 연결 중 / 재연결 중 (펄스)
    • ⚪ 끊김

7.3 라우팅 (Auto-Take)

4×8 그리드에서:

  1. 상단 입력 행에서 입력 채널 셀 클릭 (선택됨, 하이라이트).
  2. 하단 출력 행에서 출력 채널 셀 클릭 → 즉시 라우팅 명령 전송.
  3. 중간 연결 행에 현재 라우팅된 입력 별칭이 표시됩니다.

7.4 별칭 편집

입력/출력 셀을 더블클릭하면 인라인 편집창이 떠 별칭을 입력할 수 있습니다 (최대 10자).

7.5 프리셋 (v1.6.0)

자주 사용하는 라우팅 조합을 저장하고 1클릭으로 일괄 적용할 수 있습니다.

7.5.1 추가

  1. 먼저 매트릭스를 원하는 상태로 라우팅합니다.
  2. 매트릭스 제어 헤더 우측의 프리셋 + 버튼 클릭 → 모달 표시.
  3. 저장할 출력 채널 1~8 체크박스 선택.
  4. 프리셋 이름 입력 (최대 20자).
  5. 저장 클릭 → 매트릭스 그리드 위쪽 스트립에 버튼 생성.

7.5.2 적용

스트립의 프리셋 버튼 좌클릭 → 저장된 라우팅이 순차적으로 적용됩니다 (기존 Pn8080 single-flight 큐 위에서 직렬화). 8채널 적용 1.5초 이내.

7.5.3 삭제

프리셋 버튼 우클릭 → 어두운 확인 다이얼로그 표시 → 삭제 클릭 (또는 Enter) → 삭제 + 자동 재정렬.

7.5.4 제약

  • 최대 20개 까지 저장 가능. 초과 시 모달의 저장 버튼이 비활성화됩니다.
  • 매트릭스 미연결 상태에서는 프리셋 + 버튼 비활성 + 프리셋 스트립 자체가 숨겨집니다.
  • 저장 시 선택한 출력 채널의 현재 라우팅 만 캡처됩니다. 라우팅이 없는 채널(input=0)은 자동 제외.

7.6 자동 재연결

연결이 끊어지면 5단계 backoff (500ms → 1s → 2s → 5s → 5s) 로 자동 재연결을 시도합니다. 5회 모두 실패하면 끊김 상태로 남으며, 사용자가 연결을 다시 누를 때까지 시도하지 않습니다.

7.7 부팅 시 자동 연결

매트릭스 패널 하단의 앱 시작 시 자동 연결 체크박스를 켜면, 다음 부팅부터 호스트 PC가 자동으로 매트릭스에 연결을 시도합니다.

8. 운영 옵션

v1.3.0의 schema-driven OPTION_REGISTRY 패턴에 따라 모든 옵션은 한 곳에서 관리됩니다. 현재 등록된 옵션:

키 설명 값
signage.resolution 사이니지 캔버스 해상도 5760×1080 / 5760×1200
signage.mode 출력 모드 (v1.4.0+) Surround / Individual
signage.targetDisplayId 출력 모니터 지정 (v1.7.0+, 개별모드 전용) null (자동) 또는 디스플레이 ID
slide.transitionSec 페이지 전환 fade 시간 0.0 ~ 5.0초 (0.1초 슬라이더)
slide.padding 슬라이드 콘텐츠 여백 0 ~ 200px (1px 슬라이더)
슬라이더는 v1.3.0 Act-1 fix로 드래그 전체 범위에서 부드럽게 작동합니다 (pointerUp/keyUp/blur 시 commit).

9. LAN 다중 클라이언트

v1.2.0에서 추가된 기능으로, 같은 LAN 내 다른 PC/모바일에서 플레이백을 원격 제어할 수 있습니다.

9.1 사용법

  1. 호스트 PC의 IP를 확인 (Toolbar → 정보 또는 ipconfig).
  2. 다른 기기 브라우저에서 http://<호스트IP>:7321 접속.
  3. 편집기와 동일한 UI가 표시되며, PlaybackControls로 사이니지를 원격 제어 가능.

9.2 동기화 방식

  • 변경 사항은 SSE (Server-Sent Events) 로 실시간 푸시.
  • 호스트와 클라이언트 간 상태는 updatedAt staleness guard로 일관성 유지 (v1.2.2 race fix).

9.3 보안

  • localhost 외 접근은 host-device-id 기반 secret으로 인증.
  • 매트릭스 제어 패널은 host-only (Electron 환경 한정). 원격 브라우저에서는 표시되지 않음.

12. 트러블슈팅

12.1 사이니지 표시 후 컨트롤 UI가 늦게 보임

5760×1200 해상도에서 첫 클릭 시 1초 이상 지연될 수 있습니다. v1.2.2에서 race 수정으로 대부분 해소됐으나, 첫 부팅 직후에는 여전히 느릴 수 있습니다. 2~3초 대기하거나 다시 한 번 클릭.

12.2 슬라이드 전환 시 검은 화면이 보임

v1.3.0 이전에는 페이드 중 검은 화면이 노출됐습니다. v1.3.0 이후 true crossfade로 해결. 여전히 보이는 경우 앱 버전을 확인하고 1.3.0 이상으로 업데이트하세요.

12.3 매트릭스 자동 재연결 실패

  1. 로그에서 [matrix] auto-connect failed: ... 확인.
  2. 호스트 PC에서 ping <매트릭스IP> 으로 네트워크 확인.
  3. 매트릭스 본체 LCD에서 IP/Network 상태 확인.
  4. 패널의 연결 해제 → 연결 수동 시도.

12.4 프리셋 + 버튼이 비활성

매트릭스가 연결되지 않은 상태입니다. 먼저 연결을 누른 후 다시 시도하세요.

12.5 프리셋 추가 모달에서 입력이 안 됨 (v1.5 이전)

v1.6.0에서 해결됐습니다. 원인: Electron의 window.confirm 네이티브 다이얼로그가 dismissed 후 BrowserWindow를 stale focus 상태로 두는 이슈. v1.6.0부터 in-app React confirm으로 교체.

12.6 데스크탑 바로가기가 Chrome으로 열림

구버전 LNK가 http://localhost:3000으로 등록된 경우. NSIS 설치본을 새로 받아 설치하면 C:\Program Files\Smart Signage\Smart Signage.exe 로 자동 등록됩니다.

12.7 SQLite 부팅 실패 — "no such column"

v1.4.0 도입 시 mode 컬럼 migration 순서 버그가 있었으나 즉시 수정됨. 최신 버전에서는 마이그레이션이 PRAGMA table_info 검사로 idempotent하게 실행됩니다.
